# 永久服天赋模拟器 · 中英双语对照本地版
# Forever Talents — bilingual (简体中文 / English) local edition

这是 [forevertalents.up.railway.app](https://forevertalents.up.railway.app/)（魔兽世界经典旧世
「Forever / 永久服」60 级天赋计算器）的**本地副本**，界面、布局、规则、数值与原站完全一致，
但**每一处文字都做了中英双语对照**。

---

## 一、怎么打开

直接双击 `index.html` 就能用（不需要服务器、不需要联网）。

想用本地服务器打开也行，例如：

```powershell
cd forever-talents-cn
python -m http.server 8000      # 然后浏览器打开 http://127.0.0.1:8000/
```

## 二、三种显示模式

右上角有三个按钮：

| 按钮 | 效果 |
| --- | --- |
| **双语**（默认） | 中文在上、英文在下，成对显示 |
| **中文** | 只看简体中文 |
| **English** | 只看英文，和原站一模一样 |

选择会记在浏览器里，下次打开还是上次那个模式。

双语模式下的排版约定：

* 天赋名 / 树名 / 界面按钮：`武器 Arms`（中文大字，英文小字跟在后面）
* 悬浮提示正文：中文一行、英文一行，中文是金色，英文是暗金色
* 天赋格右下角 `0/3` 是「当前等级 / 满级」，两种语言通用
* 对照模式下的小圆标：中文模式显示 `新 / 改 / 移`，英文模式显示 `N / C / M`

## 三、功能（与原站一致）

* 9 个职业 × 3 棵天赋树，共 **470 个天赋、1332 条逐等级文本**，另有 105 个被移除的经典旧世天赋
* 左键加一点、右键（或 `Shift`+左键）减一点；键盘 `Enter` 加点、`Backspace`/`Delete` 减点
* 每行需要在该天赋树中先投入 5 点；箭头标出「需要上方天赋满级」的依赖关系
* 等级下拉（10–60）决定可用点数；每棵树标题上的 `↺` 单独重置该树
* **Compare with Classic 与原版经典旧世对照**：绿色 `新`=永久服新增，黄色 `改`=文本/等级/位置有改动，
  蓝色 `移`=位置变动效果相同，变暗=与经典旧世完全相同；被删掉的经典旧世天赋列在每棵树下方
* 种族特长（含永久服自制种族「天裔」），可勾选显示不能选该职业的种族

> 原站的 **Copy link / Share（复制链接、分享）**功能已按要求移除：
> 顶栏不再有「复制链接」按钮，页面底部那一行分享输入框也整条去掉了，
> 地址栏的 `#warrior/60/…` 状态串不再生成，读回状态串的代码也一并删除。
> 因此**刷新页面后加点状态会清空**——本地版就是拿来当场看天赋的，不做存档。

## 四、双语是怎么做的

* 原站的英文数据（`talents.js` / `racials.js`）**原样保留、一个字节没改**，
  天赋的位置、图标、行列、依赖关系、数值全部来自它。
* 中文数据放在 `zh-talents.js`，按「职业 → 天赋树 → 天赋 → 等级」的**下标一一对应**。
* 界面文案、种族特长、法术消耗行（`20 Rage | Melee Instant | 6 sec cooldown` 之类）在 `i18n.js` 里。

### 关于「估算等级」

原站有一部分天赋在视频里只出现了 1 级，更高的等级是程序按比例放大数字推出来的（原站用斜体标注）。
中文版**不是**在运行时做字符串替换，而是在构建时就把每一级的完整中文都生成好了，所以：

* 中文与英文在同一等级上显示的是同一组数值；
* 持续时间、距离、个数这类不该变的数字不会被误放大；
* 悬浮提示里的「第 N 级的数值由视频中出现的等级推算而来」提示与原站一致。

## 六、图标与背景

图标和背景图已经**抓到本地**（`icons/`、`bg/`，合计约 1 MB），所以断网也能正常显示。

* 5 个「永久服自制天赋」的图标在原素材站上本来就不存在
  （`ability_paladin_judgementofthejust`、`ability_hunter_survivaltactics`、`ability_hunter_lacerate`、
  `ability_shaman_mentaldexterity`、`spell_druid_feralswiftness`）——原站同样显示不出来，
  这里会退化成一个带中文简称的方块（例如「强化」）。

  把 `index.html` 里 `window.FT_ASSETS = { icon: "icons/", bg: "bg/" };` 这一行删掉即可。

## 七、交付前的自检

每次构建都会跑这几项，当前结果：

| 检查 | 结果 |
| --- | --- |
| 静态检查（eslint，`lint.mjs`）| 0 error / 0 warning |
| 结构校验（`validate.mjs`）| 9/9 职业 PASS，条目数量/顺序/等级数与英文源 1:1 |
| 逐等级数字交叉校验（`qa.mjs`）| 1332 条等级文本，**0 处需要关注的数值差异** |
| 界面词条覆盖 | 9 个职业名、24 个天赋树名、85 条法术消耗词条、7 条姿态需求、3 条视频裁切说明 —— 全部有译文 |
| 种族特长对齐 | 2 阵营 / 10 种族 / 40 条特长，与英文源逐条对齐 |
| DOM 冒烟测试（jsdom）| 62/62 通过 |
| 真实浏览器端到端（Chrome，`browser-check.mjs`）| 通过：真实鼠标悬停、加点/右键减点、语言切换、对照模式、等级/重置、分享功能确已移除、触屏底部面板 |

一条命令跑完：

```powershell
pwsh -File ../.tools/verify-all.ps1
```

> **关于测试盲区（踩过的坑）**：jsdom 以**非严格模式**执行脚本，`app.js` 里漏写 `var`
> 的变量不会报错，只会被悄悄挂到 `window` 上；而真实浏览器在严格模式下会直接抛
> `ReferenceError`。曾有一个 `tipAt` 就是这么漏掉的 —— 页面能正常渲染，但鼠标悬停
> 完全不出提示，jsdom 却全部通过。现在这类问题由 `lint.mjs`（eslint `no-undef`）
> 和真实 Chrome 的 `browser-check.mjs` 双重兜底。

> `qa.mjs` 报出的 11 处「数字不一致」已逐条人工核对，都是**中文表达习惯**造成的，
> 不是数值错误，脚本里用白名单标注了原因，例如英文 `per level the attacker is above you`
> 中文写成「每比你高**1**级」、英文 `for each second` 中文写成「每**1**秒」——
> 英文用的是词、中文用的是数字。

## 八、已知限制
* 天赋文本本来就是「从视频里人工抄录」的（原站自己的说明），个别箭头或数字可能有误——
  这是原始数据的性质，本地版没有改动任何数值。
* 永恒服原创天赋在官方中文客户端里没有对应译名，用的是符合官方风格的直译；
  经典旧世已有的天赋一律使用 1.12 官方简体中文译名。
* 原站数据里混着一些 DBC 残留的 HTML（`<br>`、彩色 `<span>`、`<!--ppl11366:…-->` 注释）。
  原站直接当 HTML 渲染；本地版统一转成纯文本，这样中英两边排版才一致。

## 九、想重新生成 / 重新验证

构建与验证脚本在 `../build/` 和 `../.tools/`（需要 Node 18+）：

```powershell
node ../build/fetch-assets.mjs     # 重新抓图标/背景图
node ../build/merge.mjs            # 把 zh/*.json 合并成 zh-talents.js
node ../build/qa.mjs               # 中英逐等级数字交叉校验

pwsh -File ../.tools/verify-all.ps1   # 一条命令跑完 lint + merge + qa + jsdom + 真实 Chrome
```
